# Connexion Codex locale — mapping de la matrice du plan

Les tests utilisent des comptes et jetons synthétiques, des signatures RS256 réelles de test et un callback loopback réel. Ils ne prouvent pas un consentement ChatGPT ni un usage réel du forfait. Le banc historique `scripts/qualification/codex.mjs` et ses résultats sont préservés.

| Scénario du plan | Preuve automatisée | Limite explicite |
|---|---|---|
| Connexion et arrêt confirmé avant succès | `connection.test.mjs` : « connexion courte, compte enregistré et témoin arrêté précèdent le succès sans secret » ; `connection-probe.test.mjs` : « seuls item assistant et tour completed corrélés prouvent le témoin » et « arrêt natif attend la fermeture observable du processus possédé » | RPC synthétique et enfant Node de test ; tour fournisseur réel non exécuté. |
| Callback hostile : state, nonce, signature, client, identité | `connection-oauth.test.mjs` : callback étranger/doublons/client incorrect, nonce/audience/issuer/expiration/authorized party invalides, audiences multiples sans authorized party, signature forgée et changement d’identité | Clés de test ; la source JWKS officielle et le compte réel restent à vérifier dans l’essai humain. |
| Refus ou scopes insuffisants, aucun témoin | `connection-oauth.test.mjs` : « refus de consentement ne tente aucun échange et ferme le listener », « scopes insuffisants et changement d’identité refusés » ; service n’appelle le témoin qu’après retour OAuth et sauvegarde | Aucun refus humain réel revendiqué. |
| Annulation, délai et fermeture pendant OAuth/témoin | `connection-oauth.test.mjs` : annulation/timeout/navigateur défaillant et navigateur non répondant ; `connection-probe.test.mjs` : annulation RPC et arrêt observé ; `connection.test.mjs` : annulation/fermeture sans rejeu, arrêt inconnu, arrêt avant queue et double fermeture | Arrêt du véritable exécutable Codex en usage fournisseur non observé. |
| Conservation et coffre illisible/chiffrement absent | `connection-vault.test.mjs` : chiffrement/écriture atomique, restauration et inscription conservée, corruption et chiffrement indisponible ; `connection.test.mjs` : restauration sans réseau et coffre illisible sans reset ; banc Electron : DPAPI réel, restauration enregistrée, déconnexion et corruption préservée | Chiffrement des tests unitaires injecté ; DPAPI vérifié séparément dans Electron. Aucun transfert de credentials utilisateur. |
| Bridge strict, secrets Main uniquement | `connection.test.mjs` : refus de secrets/URLs/commandes imprécises et événements assainis ; banc Electron : fenêtre étrangère refusée avant OAuth ; banc Windows : surfaces des deux bridges et capacité BMad indisponible | Les fonctions de test substituent le navigateur, pas le code de validation métier. |
| Témoin isolé et possédé | `connection-probe.test.mjs` : environnement sans credentials/profils hérités, demandes serveur refusées, catalogue insuffisant, manifeste/chemin/PE exigés, refus d’un profil sous le dépôt avant création | Binaire réel non lancé pendant les contrôles automatiques ; aucune équivalence wrapper/native supposée. |
| UX barre et panneau | Banc Electron compilé/paquet : une icône accessible, une commande projet, clavier/Échap/focus retour, annulation sans réseau, rappel forfait protégé et acquitté une seule fois, formats bureau/compact | Une passe initiale de captures puis une confirmation corrective ; pas d’audit lecteur d’écran/WCAG ni d’essai humain revendiqué. |

Les fichiers de tests sont sous `tests/`. Le banc nouveau est `scripts/qualification/connection.mjs`. Les résultats exacts sont dans `tests.txt`, `build.txt`, `profile.json` et `packaged-profile.json` ; le profil de régression Windows reste sous `tickets/epic-boucle-codex/qualification-g0/profile.json`.

Après revue, les régressions supplémentaires de queue et mutations à la fermeture, arrêt --version inconnu, réautorisation sans client_id et deux sorties UI ont été exécutées dans la suite complète : 83 réussites, zéro échec ou ignoré. Le consentement humain dans le navigateur système et le tour réel du paquet ont ensuite réussi ; la preuve positive expurgée est figée dans `live-confirmed-profile.json`. Le fichier ignoré `live-profile.json` est seulement le statut courant de la fenêtre. Cette réussite personnelle locale ne modifie pas G1 distribué, 1.1, 1.2 ou le tracer 1.3.
