# Qualification du thème sombre terracotta

L’extension applique une proposition anthracite chaude, terracotta pour les actions et bleu pour les liens, le focus et les repères. Le clair reste disponible depuis la commande soleil/lune de la barre ; le choix est mémorisé dans `appearance-v1.json`, séparément du Snapshot métier v1. La disposition et les flux agent restent ceux du pilote existant.

`profile.json` rapporte onze contrôles compilés avec nettoyage du profil temporaire : sombre initial et barre Windows, canevas avant amorçage dans les deux thèmes, changement clavier sans altération du Snapshot, rechargement du renderer conservant le clair sans écriture ni nouvel appel overlay, saisie et navigation en fenêtre compacte, enum invalide et fenêtre étrangère refusées sans effet, lecture courante ordonnée après les changements, restauration du clair avec historique sans moteur, fichier futur préservé avec choix de session et avertissement conservés après rechargement. Ce dernier passage utilise `--skip-screenshots`. Les trois images déjà inspectées `native-dark-desktop.png`, `native-dark-compact.png` et `native-light-desktop.png` montrent uniquement la fenêtre témoin possédée et ses vrais contrôles Windows ; aucune nouvelle capture n’a été prise pendant la réconciliation. Les données et l’historique sont synthétiques, aucun compte n’est enregistré, aucune connexion ni aucun agent n’est lancé.

Les contrastes sont calculés à partir des tokens du renderer compilé : 32 couples par palette, minimum du texte de 6,05:1 en sombre et 4,84:1 en clair ; focus et contours à 3,50:1 et 3,35:1. Les états sémantiques gardent leurs libellés. L’inspection visuelle a regroupé les trois variantes ; une seule confirmation a amélioré leur cadrage sur historique et brouillon, sans correction CSS. Ces preuves ne constituent pas un audit WCAG complet, un essai de lecteur d’écran, une acceptation visuelle humaine ou une installation.

Vérifications supplémentaires réalisées : `npm run build` (types et compilation), `npm test` (121 tests), `node scripts/qualification/windows.mjs --ui-regressions-only --skip-screenshots` (cinq régressions ciblées, nettoyage confirmé, preuves historiques inchangées). Le sandbox Windows refuse `rename()` dans son Temp ; les tests d’écriture atomique et les bancs Electron ont été exécutés avec l’autorisation de qualification hors sandbox.

Deux revues Quick ont relevé deux constats, tous deux corrigés : amorce périmée au reload (R1), puis fond sombre pendant la lecture du thème clair (R2). La lecture courante utilise le même pont validé et la même file que les changements ; elle conserve les avertissements de session et ne touche ni à la préférence ni au Snapshot. Le canevas non amorcé est transparent avec `color-scheme: normal`, laissant le fond natif courant apparaître ; le banc vérifie les styles calculés et la couleur native, sans mesure vidéo ni nouvelle capture.

Après les corrections, types/build et les 121 tests passent de nouveau ; cinq régressions Windows ciblées et onze contrôles du programme empaqueté passent aussi. `packaged-profile.json` et `verification.json` identifient ce résultat et le paquet `dist/terracotta-pilot/`, avec empreintes de l’installateur et de l’archive. Aucun correctif différé. Les profils témoins sont nettoyés ; la livraison personnelle est consignée ci-dessous.

Relancer le banc compilé : `node scripts/qualification/theme.mjs --skip-screenshots`. Pour un paquet, utiliser `node scripts/qualification/theme.mjs --executable=<chemin-absolu-vers-Madness.exe> --skip-screenshots` ; cette variante écrit `packaged-profile.json` sans remplacer les captures et la preuve compilée. Aucun gate distribué ni ticket n’est clos par ce lot.

Livraison personnelle : le porteur confirme la fermeture et autorise l’installation. `installation.json` confirme le code installateur 0, l’archive identique au paquet testé, le snapshot et le compte chiffré inchangés après installation puis réouverture. La fenêtre installée est ouverte normalement et répondante, avec configuration sombre par défaut. Aucun débogueur ni action fournisseur n’est utilisé pour cette vérification ; le thème configuré et l’identité du paquet sont contrôlés, sans nouvelle inspection visuelle sur données personnelles. L’acceptation visuelle humaine reste distincte.
